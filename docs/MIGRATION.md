# Migrer une installation V2

1. Inventorier le trail et son compte propriétaire, les destinations, les clés, les sélecteurs, les détecteurs existants, les principals et leurs exceptions. Sauvegarder le state dans un emplacement contrôlé. Conserver une preuve de livraison récente.
2. Si la remédiation V2 est activée, suspendre sa cible Lambda pendant la migration. Maintenir l’écriture des logs et les notifications. Le nouveau contrôle commence en lecture seule. Ne pas fusionner les deux anciens exemples de variables.
3. Utiliser une copie du state pour examiner la migration du provider AWS 5 vers 6. Le bloc `moved` conserve le trail lab à la nouvelle adresse indexée. Examiner tout remplacement, changement de bucket, de KMS ou de rétention. La V3 n’effectue aucune migration implicite du state local vers le backend S3.
4. Pour conserver la propriété Terraform de détecteurs gérés par V2, régler explicitement `manage_guardduty_detector` ou `manage_securityhub_account` à true avant le premier plan V3. Un passage de true à false d’une ressource déjà dans le state peut planifier sa suppression. Transférer explicitement la propriété à l’administrateur cible en conservant la ressource. Utiliser des blocs `import` pour les ressources existantes qui doivent passer sous gestion.
5. Créer l’archive d’organisation sous un nouveau nom. Un bucket existant ne change pas de compte propriétaire. Ne pas gérer le même trail d’organisation depuis deux states. S’il existe, préparer son import dans Management, vérifier ses sélecteurs et sa destination, puis préparer la bascule. Si un trail temporaire supplémentaire est requis, borner sa durée et son coût.
6. Déployer les capteurs pilotes, confirmer les abonnements et recueillir les preuves de matrice. Conserver les journaux V2 et leurs clés selon leur durée prévue. Retirer l’ancien routage seulement après vérification des deux régions et du compte membre.
7. Pour revenir en arrière, rétablir la dernière configuration connue, son accès aux clés et les routes précédentes. L’activation Object Lock engage le bucket dans la durée. Une ancienne version de state ne constitue pas à elle seule une restauration des ressources AWS.
